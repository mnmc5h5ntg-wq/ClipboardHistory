## 2. 这一屏"够不够华丽/够不够原生"的重判（不许假设现有决定是对的）

结论：**不加任何东西**。理由分三层，都不是"已经有人决定过"：
① 这一屏的信息密度全在颜色上，而颜色的相邻档差 20–40/255 已经贴着"看得出来"那条线（18），
再叠一层动画只会让某一帧的档位暂时不可读；
② 原生对照物是"系统设置里的统计/日历类页面"和 GitHub 的贡献图，两者都是静置的；
③ 唯一真正"该华丽"的地方是 hover —— 而它已经有了（描边 + 提示），并且有判据。
反过来说，如果这一屏缺什么，缺的不是动效而是**暗档侧栏那一条还没有可信读数**（§3-D4）。

## 3. 本轮看图看出来的东西（含仪器自己的失效）

- **D1（复现到同一族，但不是同一份读数）**：亮档侧栏四枚未选中图标在离屏帧里"不存在"——
  `≥8/255 的像素 0 颗、最远 4/255、极值色号是纯白 (255,255,255)`。这与产品源码
  `SettingsView.swift:808–815` 里 R30 记下的那条（`OffscreenSymbolInkProbeTests` 量到墨水比 0.0000，
  换成固定 `Color.black` 能到 0.175–0.402）是同一族：**离屏管线对语义色的解析**，不是产品。
  **但两次的读数不一样**：R30 那份是 `settings-data` 帧上"未选中四行 0.0000"，
  今天这张 `settings-stats` 帧上是**四枚为 0、推荐那一枚可见**（143 颗 ≥40，极值纯黑 (0,0,0)）。
  ⇒ 同一列里出现了两种解析结果，说明"离屏把语义色解析成什么"还取决于**符号本身**
  （`wand.and.stars` 与另外四枚不同）。这条差异本轮不定性，开成 BACKLOG **126**，
  并且那里写了那个能一次分开的实验：**同一屏拿真机窗口截图（`screencapture`）与离屏帧对一次**。
  这台机器上就能做，不该再挂在"等用户真机"那一栏。
  还要看清它坏在哪：本轮我先用眼睛看，写下的描述是"图标偏淡"——**淡是错的，是不存在**。
- **D2（仪器失效，已修）**：R88 那把侧栏尺写的是 `maxc(p) - bg >= 40`，只认**比背景亮**的墨。
  亮档的黑字在它眼里等于没有字 ⇒ 实测 `文字带=0 个`。
  也就是说 R88 之后"亮色侧栏没问题"这句话**从来不是读数，是没量到**。
  本轮的新尺改成双边距离并打印极值色号，才第一次量到亮档标签 251/255。
- **D3（历史读数身份错位）**：本轮按**结构**推列（先扫分隔线，再切列段）得到
  图标 x=35–68 / 标签 x=79–153 / 分隔线 x=296，而 R88 的常量是"图标 88–150 / 文字 170–420"——
  整整错开一列，它那个"文字框"落在**内容区**里。
  ⇒ 翻回 R88 那句"图标里推荐与统计两行也只有 28"：它量的是 x=88–150，也就是**标签列**，
  所以那句话的**内容仍然成立**（暗档标签黑字黑底），但**主语写错了**。本轮不改 R88 的历史文本，
  在这里把身份改正过来，并让新仪器不再抄常量。
- **D4（新仪器还没赢的地方，诚实记）**：暗档两张帧上 `COLUMN_SEGMENTS=1` ⇒ NOT-RUN。
  原因是分隔线在暗档只有 ~10/255，门槛被迫降到 8/255，于是 vibrancy 噪声把图标列与标签列连成一段。
  修法很轻（列位置从**同主题的亮档帧**推，或用行投影切列），本轮不做——一次只改一处。
  在修好之前，暗档侧栏逐行读数只有 R88 那一份。
- **D5（口径）**：`距卡片底` 一开始用"最大通道减背景"，对蓝色格恒等于 −3（蓝格蓝通道本来就≈255），
  会把最显眼的东西读成看不见 ⇒ 换成逐通道最大绝对差，并把参照点从"整页中位数 255"换成
  **网格左边那条窄带的中位数 243**（整页与卡片差 3/255，用整页当参照会把格子的深度读少）。

## 4. 自检（这台仪器凭什么能被信）

① 正对照：两张空态帧必须量不到蓝 ⇒ 实测 `NO_BLUE_CELLS`（亮/暗都走到这一格）。
② 区域不猜：网格包围盒、图例带、侧栏列全部由检出像素推出来并打成 pt 坐标。
③ 反对照：`CROSS_MODE light簇=5 dark簇=5 交集=0` ⇒ 两张帧确实是两个主题，色号没有串。
④ 格式串 arity：所有输出走 `F()`，占位符数 ≠ 参数数直接抛 —— 本轮它真的抛过一次
（第一次跑就 `TypeError`，那条读数没有半截落盘）。
⑤ 参照点污染：图例那一带的"卡片底"取到了别处的蓝（`CARD_SAMPLE_CONTAMINATED`），
脚本自己把它标出来，那一带的"距卡片底"不许引用。

## 5. 本轮改了什么、值不值这个分数

本轮零产品文件改动（7 个非台账文件全在 CI/测试/脚本/夹具里），所以七维里"原生感/流畅度/层次与材质"
三格本轮**没有脸加分**，也没有东西被扣；真正被推进的是"这一屏的读数第一次可信"这件事。
分数与欠账写在 `AGENT_VISUAL_ITERATION.md` 第 92 轮那一节。
