## 2. 一条把 BACKLOG 127 判掉的读数（本轮的正对照）

新加的诊断判据 `testRowProxyCensusAsksTheConsequenceNotTheShape`（本机实测，整卷 11 条 15.438 秒）：

```
ROW_PROXY_TRUTHTABLE 同行(差1pt)=1组 两行(差25pt)=2组 阈值=2pt
ROW_PROXY_CENSUS 侧栏@窗口320pt 宿主=320pt 代理=2 行=1 首行各代理宽=[148+148]
ROW_PROXY[0] frame={{12,50.5},{148,25}} acceptsFirstResponder=false next=KeyViewProxy@{{160,50.5},{148,25}} 父链=KeyViewProxy ← NSHostingView
ROW_PROXY[1] frame={{160,50.5},{148,25}} acceptsFirstResponder=false next=AppKitPlatformViewHost<…SelectedRowRevealer>@{{0,126},{320,334}} 父链=KeyViewProxy ← NSHostingView
ROW_PROXY_LISTROWS 行视图=11 个，前 3 个={{0,10},{320,66}} {{0,76},{320,51}} {{0,127},{320,66}}
ROW_PROXY_CENSUS 侧栏@窗口250pt … 首行各代理宽=[113+113]
ROW_PROXY_CONTRAST 浮层(NSTableView) 代理=0 行=0
```

⇒ 定性是 **②：判据的期望写错**，不是产品的无障碍结构坏。三条证据：
1. 11 行的侧栏树里只有 **2 个** `KeyViewProxy` ⇒ 它**不是行代理**（行是 `ListTableRowView`，11 个、整行宽 320）；
2. 两个都 `acceptsFirstResponder=false` ⇒ Tab 不会停在它们身上，"一行停两次"这件事没有发生；
3. 半宽**跟着宿主宽度缩放**（320→148+148；250→113+113），父视图直接是 `NSHostingView` ⇒ 那是 SwiftUI 宿主级的 key-view 代理，与"这一行"无关。

所以修法不是把 `宽 200…290` 放宽成"148 也行"（127 明写不许：那是拿判据讨好现状），
而是**改成点真正的行视图** —— 这条判据要的是"用户点一行"，与代理无关。
改后：`testSidebarListFocusRingAfterClick` 从红变 `passed (0.738 seconds)`，
`RINGVIEWS 总数=2 覆盖整块列表的=[]` ⇒ 整卷 **11 tests / 3 skipped / 0 failures**，
main 上那朵"有名字的红"（R91 有意留下的）到此消失，而且是**被证据判掉的**，不是被静音的。

顺带一条我自己的错（U-216）：第一版的"后果"读数是走 `nextKeyView` 链，我差点据此说
"Tab 在同一行停两次"。`acceptsFirstResponder=false` 打出来之后才知道：
**在链上 ≠ 会被停在上面**。⇒ 读数现在同时打 `acceptsFirstResponder`，两件事分开记账。
