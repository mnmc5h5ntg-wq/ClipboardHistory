## 0. 通道前提（先说清楚哪些格子今天没资格判）

`capture-readings.log` 现场写着 `面板key=false appActive=false`。
**这条前提砍掉了本轮两个本来想判的问题**：

- 「清空」那颗是 `Button(role:.destructive).buttonStyle(.borderedProminent).tint(.red)`
  （`SettingsView.swift:658-663`，改前是 661-663）。红来自系统 accent，
  而 AppKit 在非 key 窗口里把 accent 去饱和成灰 ⇒ 帧里三颗按钮填充完全相同（235/235/235）
  **不能**读成"破坏性那颗没被区分"。这一格 `NOT_RUN=ACCENT_IN_NON_KEY_CHANNEL`。
- 侧栏那颗选中胶囊：亮 rgb(217,229,251) / 暗 rgb(28,43,64)，标签蓝 rgb(6,113,245) / rgb(2,120,252)，
  算出来对比 3.53 / 3.47。同样是 accent 派生色 ⇒ 这个 3.5 是**通道**的读数，
  不是产品给人的对比度。真机 key 窗口那一档没判（BACKLOG 130）。

## 2. 本轮真正改的那一条：分组语言

同一窗口五种分区，四套语法（本机量出来的，`GROUPING` 行）：

| 分区 | 卡片 | 卡片**外**分隔线 | 卡片**内**分隔线 |
| --- | --- | --- | --- |
| 通用 | 1 | 0 | 0 |
| 快捷键 | 1 | 0 | 2（156pt、214pt） |
| 隐私 | 1 | 0 | 3（45pt、262pt、328pt） |
| 统计（有数据） | **0** | **1**（271pt） | — |
| 数据（改前） | 1（只圈两段说明） | **2**（173pt、282pt） | 0 |

「数据」是唯一一个"卡片只圈住一部分、其余整段裸在外面、外面还压着分隔线"的分区。
本轮把它向**多数**（快捷键 / 隐私那套 `GroupBox + VStack(spacing:12) + 内部 Divider()`）靠拢。
统计页那套（0 卡片 + 1 条外线）没动 —— 它是阶段一新功能，改它要和热图那屏一起判，开成 BACKLOG 131。

改后（同一把尺，亮/暗一致）：

| 读数 | 改前 | 改后 |
| --- | --- | --- |
| 卡片框 | (172,106)..(696,**158**) | (172,106)..(696,**318**) |
| 卡片外分隔线 | 2 条（173、282） | **0 条** |
| 卡片内分隔线 | 无 | **2 条（166、271）** |
| 三颗按钮 | 86x24 / 86x24 / 50x24，填充 235 | 86x23 / 86x23 / 49x23，填充 228（卡片上合成） |
| 说明段对比 | 3.59 | 3.64（与通用 3.74 同档） |
| 内容最低 | y=324pt | y=318pt |

三颗按钮的填充改前改后**互相都相同**（差=0），说明这次没有把任何一颗的层级改掉；
变的只有容器。段内动画键（R42 那两条 `.animation(value:)`）、回执通道、禁用逻辑一行未动。

## 3. 加动效的判断（这一屏每一个可动位点）

| 位点 | 加不加 | 理由 |
| --- | --- | --- |
| 卡片容器本身（本次新增的包裹） | **不加** | 它是一次布局变更不是状态变化；给容器加淡入会让"打开这一页"变成一次表演 |
| 两条内部分隔线 | **不加** | 静态分组线，没有前后态 |
| 导出/导入回执 `ReceiptLine` | 保持现有 `.contentFade` | R43 已判过两条通道，本轮不动 |
| 清空回执（图标+数字） | 保持现有 `.contentFade` + 布尔键 | 同上，键仍是"有没有回执" |
| 「清空」按钮 hover | **不加自定义** | `.borderedProminent` 系统自带 hover/按下档；自定义会盖掉 destructive 那套语义 |
| 侧栏行 hover | 不加 | R74 量过重排次数那一族，已定"不淡入" |
| 说明段 hover 提示（tooltip） | **不加** | 说明段本身就是给人读的正文，加 tooltip 是把已经摊开的话再藏一层 |

## 4. 本轮我自己错掉、并且被读数纠正的四条

1. **Q2 的第一版结论"破坏性那颗没有被区分"是错的** —— 我拿"三颗填充相同"当产品结论，
   没先读通道前提（`appActive=false`）。同一次我先怀疑过"是不是禁用态"，去查了 fixture
   （`clearHistoryAction: { nil }` 是**非 nil 闭包** ⇒ 按钮是启用态），那条排查方向对、
   结论仍错：真正的解释是 accent 在非 key 窗口去饱和。⇒ 仪器现在把前提打在 `PREMISE` 行里，
   Q2/Q3 在 non-key 时只能出 NOT-RUN。
2. **胶囊检测器抄了 R90 的"色相 ≥25"常数** —— 这颗胶囊实测色相 22（亮）/21（暗），
   两档都差 3 没检出，于是 Q3 被读成"今天没判"。给没量过的色号写阈值，就会把量到的东西读没。
   现在换成相对判据（这一列里色相最大 + 与侧栏底色差 ≥12 + 高宽门槛），并把两个数一起打出来。
3. **"卡片内线"第一版参照的是页面底色** —— 那样"其余分区 0 条内线"是假的：
   卡片内部的线比的是卡片底色。改成拿卡片自己的底色当参照，并要求整行**同方向**偏离 ≥90%，
   卡片自身描边（边缘 1~3px）让开 13pt。
4. **改完之后按钮填充一度报成 247（= 卡片色）** —— 我把卡片色当按钮填充传了进去，
   于是"墨"里混进了按钮自己的灰底。改成取盒子自己的中位色（228/54）后，
   改前改后的"三颗同填充"才是可比的。
