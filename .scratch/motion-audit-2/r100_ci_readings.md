# R100 推送之后要在 CI 里读什么（写于推送之前，避免事后按读数编问题）

本轮推送的是**判据**，不是产品：横向内缩尺 + 两条能力闸门 + 一条绝对锚点。
所以 R100 的 CI 只有三格有信息量，其余都是"没弄坏东西"的对照。

## ① 147 的那一格：`CARD_BAND` 在 runner 上现在打什么

本轮之前的样子（run `38913173905`，二十格全一样）：

```
CARD_BAND settings-data light 页底=236 填充=-1 墨行=0 卡片段=0 窗口高=540 带子=60..540 位图=720x540 行数=480 scale=1.0
```

本轮之后要看的是**同一格里 `页底` 与 `填充` 这两个数**。三种形状三种下一步：

| 形状 | 读法 | 下一步 |
|---|---|---|
| `填充=-1` 且 `页底` 仍是 236/52 | 卡片填充与页面底差 ≤3 ⇒ `cardFill` 第一关就没过 | 147 定性为"runner 不合成半透明材质" ⇒ 这一族登记成**只有本机能判**，并给这一族换一条不依赖材质分离的左轴（先例 R26） |
| `填充=<某个数>` 而 `卡片段=0` | 材质读到了但过不了"最长连续材质 ≥30%"那一关 ⇒ 是 1x 光栅把 8 档差摊平/把边糊掉 | 147 定性为**分辨率问题** ⇒ 门槛按 `scale` 分档（不许直接放宽，要量出 1x 上真实的那一档） |
| `填充=<某个数>` 且 `卡片段>0` | 本轮改动把它救活了（最不可能的形状） | 147 结案，并回头查 R95–R99 那几轮在 runner 上到底为什么是 -1 |

**判据自己会说什么**：两条判据在材质格=0 时 `throw XCTSkip`，理由里带两机的页底/填充。
所以 runner 上应当看到 `skipped` 比上一次 +2（竖向名单 + 横向内缩），
而 `CAPTURE_GATE_CASES` 的 `failed` 应当从 1 回到 0、`passed` **不许多也不许少**（46 上下）。
`passed` 若掉了 ⇒ 说明有别的用例被本轮改动连带 skip 了，那是新伤，要单独查。

## ③ 新夹具的两帧：`cardprobe-groupbox-default-*` 会不会像 R28b 那样在 runner 上整帧 0 墨

本轮新增 2 张帧（128 → 130）。R28b 那一族是"900pt 与 1100pt 两档在 runner 上整帧读不出墨，
而 ≤750pt 的 100 张从来没问题"。这张夹具是 **720×140**，落在"从来没问题"那一档，
但它的**高度只有 140pt**，比仓库里任何一张帧都矮 ⇒ 如果 runner 上它对 `frame_baseline` 报
`CHANGED`（而不是 MISSING/ADDED），那矮帧也是一条新的通道边界，要登记而不是重画基线。

## ④ 本轮推送前会补上的一格诊断（把 147 从"下一次再猜"变成"下一次一定答"）

**先确认过的坏消息**：workflow 里**没有** `upload-artifact` 步骤（`grep -n upload-artifact .github/workflows/*.yml` 无命中），
所以 runner 拍出来的 PNG 拿不回来 —— 147 那个"runner 上卡片填充到底是多少"的问题，
**没法从已有的任何一次 run 里回答**，只能等一次带新读数的 run。

**因此本轮在 `testSettingsCardVerticalRhythmIsOneNumber` 的 `CARD_BAND` 旁边补一行**：
当 `cardFill` 返回 nil（`fill < 0`）时，把**那一带逐行众数的前三名连同各自占多少行**打出来：

> **收尾更正（已落地；R101 别照抄上面那段设计稿的格式）**：实际打的形状是
> `CARD_FILL_CANDIDATES <夹具> <档> 页底=<luma> 前三=(色号:行数) (色号:行数) 门槛=abs(档-页底)>3且行数/倍率>=20pt`
> —— 条目之间是**空格**不是逗号；`前三` 里**含页底那一档**（这正是区分两种缺法的根据）；空档时打 `前三=无`。
> 纵向与横向两把尺都打（`fillCandidatesLine` 是同一颗纯函数），证人吃的是 `cardRowKinds` 交回的**同一个数组**。
> **本机对照读数**：`settings-stats light 页底=252 前三=(252:960)`、`settings-stats dark 页底=28 前三=(28:960)`、
> `settings-stats-populated light 前三=(252:958) (228:2)`、`settings-stats-populated dark 页底=28 前三=(28:958) (52:2)`
> ⇒ 共 **4 行** = 两屏 × 两档，其余 22 格有材质、不打这一行
> （`CARD_INSET_CAPABILITY 候选=26 有材质=22`、`CARD_ABOVE_CAPABILITY settings格=24 有材质=20`）。
> **runner 上按顺序问三句**：① 这一行有没有出现（没出现 ⇒ 判据没走到那一步，先修「为什么没走到」，再谈 147）；
> ② 出现了多少行（本机 4；若 runner 上等于候选数 ⇒ 那台机器连材质都没有，是通道问题）；
> ③ 每行的前三名里，除页底那一档以外**有没有行数够 20 的档**（有 ⇒ 门限问题，
> 按两机实测分离度重标 `gate`：真机 16 / 本机 7~8 / runner ≤3，不许凭感觉放宽）。

```
CARD_FILL_CANDIDATES settings-privacy light 页底=236 前三=(236:471, 239:4, 12:6) 门槛=abs(modal-页底)>3
```

这一行把三种形状彻底分开，而且**不需要 runner 的像素**：

| 读数 | 结论 | 下一步 |
|---|---|---|
| 前三名里有一项 ≠ 页底且占比 ≥20 行 | 材质在，只是差 ≤3 被 `cardFill` 的门限挡掉 | 147 = **门限问题**：按两机实测的分离度重标 `gate`（本机 8、真机 16、runner ?），不许凭感觉放宽 |
| 前三名全是页底 | runner 上 `GroupBox` 根本没画出一层材质 | 147 = **通道问题**：这一族登记成"只有本机能判"，并给卡片找一条不依赖材质分离的左轴（先例 R26） |
| 那一行压根没打出来 | 判据在那台机器上没走到这一步 | 先修"为什么没走到"，再谈 147 |

**为什么现在补**：这一格不加，下一次 CI 仍然只能告诉我最多"填充=-1"，
而那是**我已经知道的**——它不缩小成因空间。加了它，一次 run 就把三种可能压成一种。
