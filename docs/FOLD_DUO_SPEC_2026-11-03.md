# 折叠/展开 = Duo 式折页 · 决策定稿（2026-11-03 与用户逐题确认）

这份文档是实现的**唯一依据**。任何一条与它冲突的做法，要么先改这份文档并写明理由，要么不做。
逐题质询的过程在会话里，这里只留结论、被否掉的选项、以及还没验证的假设。

## 0. 现状与为什么要重做

- R552 把折叠/展开的过渡**撤成了一步切换**（决定 D-552，欠账在 BACKLOG 631）。撤的理由是三条路都被真机读数否掉：
  1. 旧实现（t=0 翻状态 + 60Hz 逐拍 `setFrame(display:true)`）：切换那一拍主线程空窗 60ms（折叠）/106ms（展开），屏上 50ms 内只换 4 帧 ⇒ 先卡一下再整窗跳。
  2. 快照盖子：`cacheDisplay` 拍不出侧栏材质，那一块在窗口服务里是纯黑。
  3. 几何交给窗口服务（`animator().setFrame`，`display:false`）：屏上右缘只给出 3 档（750→535→302），中间帧不存在。
- 用户否掉“一步切换”作为终态，要求做成 iPhone Duo 那种折页，并要求先查真机与开源参考再定做法。本文档就是那次质询的结果。

## 1. 对标与参考（只借思路，不搬代码/素材）

| 参考 | 拿到的东西 |
| --- | --- |
| Apple HIG《Designing for iPhone Duo》 | 半折叠时系统把分栏左栏**拓宽到整整 50%**；折叠只移动“不动就看不见”的元素；控件突然消失或大幅跳位会让人难以追踪；折痕是“保留区域”，弹窗/菜单自动避让 |
| elijah-semyonov/DuoLikeAnimation（Swift，MIT） | 完整模型与参数：固定平面、只转封面那半、射线重投影、间隙→模糊半径、模糊→暗化、平面外为纯黑；`blurSpread 0.12`、`darkening 0.015`、32 抽样 Vogel 盘、眼距 320mm |
| lqSky7/iphone-duo-macos-animation（macTilt）、tgtools123/NUEM | macOS 原生做法与 120Hz 稳定性；“画面在空间里不动，硬件扫过它”的表述 |
| chuspeeism/iphone-duo（Three.js 研究） | 最大模糊半径 72 源像素；暗化取过渡强度的两倍并截到黑；完全展开时外屏熄灭 |

## 2. 决策清单

- **D1 画面模型**：整幅 UI 钉在一个固定空间平面上，视点不动，**只有会折的那半绕中缝转**；画面不缩放、不重排、不交叉淡。射线落到平面内容之外 ⇒ **纯黑**。
- **D2 折角范围**：0°→90°（边对视线）。**不画背面**，不做到 180°，不做回弹。
- **D3 非均匀模糊**：模糊半径 ∝ 该像素处玻璃与平面的间隙 ⇒ 靠铰链清晰、靠自由边最糊；展开时按同一函数恢复。亮度按同一间隙单调下降。禁用“整体加一层均匀模糊”代替。
- **D4 透明让位 + 框架只缩一次**：窗口改为非不透明；折页期间**窗口框架不动**，右页 alpha 归零；归零之后框架一次性缩到折叠宽（那块已经是桌面，看不出跳）。展开对称：框架先跳到展开宽（让出的仍是透明），再把右页转回来。透明区必须点击穿透，阴影跟随可见形状而不是框架矩形。
- **D5 几何**：默认 **848×600**，两栏严格各 424（50/50）；**锁 √2 比例**，但锁的方式是**拖边角时按比例缩放**（`contentAspectRatio`），不是拖完弹回。折叠 = 高度不变、宽度对折；两态因此天然都是 √2 矩形，切换时把锁定的比例值一起翻过去。
- **D5a 实测补注（R567 落地这一段时读到的两条，写文档而不是改判据）**：真窗口的 `dividerThickness` 现读 **1.00pt** ⇒ 「内容宽 848」与「两栏各 424」不能同时严格成立。落地的形状是 **423.5 + 1 + 423.5**：两列等宽、**分隔条中心**正好在 424 = 848/2。两条尺一起钉这条等式 —— 机制那把（`FoldGeometryReanchorTests`，读 `minimumThickness/maximumThickness` 并用 `setPosition(300)` 真去拖一次）与像素那把（`UICaptureTests/testTheSeamInTheRenderedFrameSitsAtHalfTheContentWidth`，帧里现读缝列 424.5pt）。默认高那个「600」在三个口径下分别是 `contentRect(forFrameRect:)=632`、`contentView=632`、`contentLayoutRect=580`（折叠态那条 layout 会变 600，因为工具栏隐掉了），**没有哪一个正好等于 600** ⇒ 600 今天只有「产品请求的内容尺寸」这一个所指，能判的只有「折叠不许动整窗高」（现读 632→632）。这两格的取舍记 BACKLOG 644，**归用户**；本轮不擅自把哪个口径钉成「真正的内容尺寸」。
- **D6 版本分叉**：macOS **14+** 演全套（Metal 着色器：透视 + 渐进模糊 + 暗化）；macOS 12/13 演同一套几何与暗化、模糊退化为近似或不做。**README 的“macOS 12+”承诺不动**。两条路共用同一个“角度驱动”模型，判据与帧按系统版本分开口径（与既有 1x/2x 分口径同法）。
- **D7 触发**：双击列表上方“时间剪史”标题 + 可见的折叠按钮（带 `.helpLabel`）+ 应用菜单项 + ⌘\，四条入口走同一个 action。**不做手掰（scrub）**，以后另议。**系统分栏的中缝拖拽要禁掉**（两栏锁等宽之后它只会让人拖出不对称）。
- **D8 设置页调参面板**：放**五根滑杆**——速度（120–600ms）、模糊强度（0–1）、明暗变化（0–1）、眼距（400–2000pt，默认按桌面尺度折算约 900）、缓动曲线（4 预设，默认 ease-in-out）——外加“恢复默认”。不做隐藏调试器。滑杆必须复用现有 `.slider` 路径，并接进“恢复默认”的复位名册（现名册是九根）。每根滑杆都要能推动读数：推到两端读数不变 = 死控件 = 缺陷。
- **D9 样片**：设置页内一块约 260×180 的假“两页 + 中缝”，**必须调用主窗口同一套折页代码**（同一着色器、同一角度映射），内容只用固定测试文本，**不得出现用户真实剪贴板内容**。不允许为样片另写简化渲染（那是典型假绿：样片好看、主窗口难看）。
- **D10 reduce-motion**：系统开启“减弱动态效果”时时长为 0，一步到位，不留任何中间态。
- **D11 可中断**：过渡中再次触发以当前角度与当前 alpha 为起点反向，不排队、不留半折。
- **D12 验收**：逐帧硬判据 + 用户手感签字，**两边都过才算完成**；任一边不过就退回一步切换，并把“为什么这条观感做不到”写进台账。硬判据至少包含：角度单调、投影宽度按余弦律、模糊半径从铰链到自由边单调递增、亮度随角度单调下降、边框锐度不变、透明区 alpha 归零、框架只在透明之后缩一次、屏上帧间隔不超标。

## 3. 交付顺序（分几轮不重要，顺序是闸门）

1. **几何与读数重锚**：默认尺寸、50/50、锁比例、禁中缝拖拽；把引用 280/750 的判据与 356 张基线帧重锚。不动画。
2. **透明与框架**：非不透明窗口、点击穿透、阴影跟随形状、alpha 归零后框架缩一次；仍是一步切换。**这一轮要回答三个问题**（见 §4）。三问任一不过 ⇒ 停在这里，不写着色器。
3. **折页着色器**：角度驱动的透视 + 渐进模糊 + 暗化，14+ 全套、12/13 退化；逐帧判据与胶片。
4. **设置面板与样片**：五根滑杆 + 复位名册 + 共用代码的样片 + 每根滑杆的“推得动读数”判据与刀。

## 4. 还没验证的假设（第 2 轮的靶，谁也不许先当成已成立）

- 非不透明窗口下，侧栏的 vibrancy 材质会不会变淡或发花（材质的背景从“窗口自己”变成“桌面”）。
- 窗口阴影是否真的按内容 alpha 形状计算，从而不会在透明区拖出一条矩形阴影。
- 现有取证通道（离屏捕获与真机截图）**能否区分“真黑”与“透明”**；不能区分则动画做完也验不了，这本身就是阻塞项。

## 5. 与本特性无关但仍挂着的一件事

反复弹“想访问桌面文件夹”的根因是每轮重装都用临时签名（ad-hoc）重签，TCC 把它当新 App。固定签名身份已建在登录钥匙串，但**需要用户在“钥匙串访问”里对 `ClipboardHistory Local Signing` 点一次“始终信任”**才能生效；在此之前弹窗照旧。撤回方式见 D-553。
