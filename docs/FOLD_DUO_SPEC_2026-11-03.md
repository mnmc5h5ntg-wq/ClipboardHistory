# 折叠/展开 = Duo 式折页 · 决策定稿（2026-11-03 与用户逐题确认）

这份文档是实现的**唯一依据**。任何一条与它冲突的做法，要么先改这份文档并写明理由，要么不做。
逐题质询的过程在会话里，这里只留结论、被否掉的选项、以及还没验证的假设。

## 0. 现状与为什么要重做

- R552 把折叠/展开的过渡**撤成了一步切换**（决定 D-552，欠账在 BACKLOG 631）。撤的理由是三条路都被真机读数否掉：
  1. 旧实现（t=0 翻状态 + 60Hz 逐拍 `setFrame(display:true)`）：切换那一拍主线程空窗 60ms（折叠）/106ms（展开），屏上 50ms 内只换 4 帧 ⇒ 先卡一下再整窗跳。
  2. 快照盖子：`cacheDisplay` 拍不出侧栏材质，那一块在窗口服务里是纯黑。
  3. 几何交给窗口服务（`animator().setFrame`，`display:false`）：屏上右缘只给出 3 档（750→535→302），中间帧不存在。
- 用户否掉“一步切换”作为终态，要求做成 iPhone Duo 那种折页，并要求先查真机与开源参考再定做法。本文档就是那次质询的结果。

## 2. 决策清单

- **D1 画面模型**：整幅 UI 钉在一个固定空间平面上，视点不动，**只有会折的那半绕中缝转**；画面不缩放、不重排、不交叉淡。射线落到平面内容之外 ⇒ **纯黑**。
- **D2 折角范围**：0°→90°（边对视线）。**不画背面**，不做到 180°，不做回弹。
- **D3 非均匀模糊**：模糊半径 ∝ 该像素处玻璃与平面的间隙 ⇒ 靠铰链清晰、靠自由边最糊；展开时按同一函数恢复。亮度按同一间隙单调下降。禁用“整体加一层均匀模糊”代替。
- **D4 透明让位 + 框架只缩一次**：窗口改为非不透明；折页期间**窗口框架不动**，右页 alpha 归零；归零之后框架一次性缩到折叠宽（那块已经是桌面，看不出跳）。展开对称：框架先跳到展开宽（让出的仍是透明），再把右页转回来。透明区必须点击穿透，阴影跟随可见形状而不是框架矩形。
- **D5 几何**：默认 **848×600**，两栏严格各 424（50/50）；**锁 √2 比例**，但锁的方式是**拖边角时按比例缩放**（`contentAspectRatio`），不是拖完弹回。折叠 = 高度不变、宽度对折；两态因此天然都是 √2 矩形，切换时把锁定的比例值一起翻过去。
- **D5a 实测补注（R567 落地这一段时读到的两条，写文档而不是改判据）**：真窗口的 `dividerThickness` 现读 **1.00pt** ⇒ 「内容宽 848」与「两栏各 424」不能同时严格成立。落地的形状是 **423.5 + 1 + 423.5**：两列等宽、**分隔条中心**正好在 424 = 848/2。两条尺一起钉这条等式 —— 机制那把（`FoldGeometryReanchorTests`，读 `minimumThickness/maximumThickness` 并用 `setPosition(300)` 真去拖一次）与像素那把（`UICaptureTests/testTheSeamInTheRenderedFrameSitsAtHalfTheContentWidth`，帧里现读缝列 424.5pt）。默认高那个「600」在三个口径下分别是 `contentRect(forFrameRect:)=632`、`contentView=632`、`contentLayoutRect=580`（折叠态那条 layout 会变 600，因为工具栏隐掉了），**没有哪一个正好等于 600** ⇒ 600 今天只有「产品请求的内容尺寸」这一个所指，能判的只有「折叠不许动整窗高」（现读 632→632）。这两格的取舍记 BACKLOG 644，**归用户**；本轮不擅自把哪个口径钉成「真正的内容尺寸」。
- **D5a 第二条补注（R568，runner 首跑读到的：同一几何量在 1x 与 2x 不是同一个对象）**：列锁本身在两台上都落地（runner 逐字 `FOLD_GEOMETRY_ITEMS … min=423.5 max=423.5`、`FOLD_GEOMETRY_DRAG_PROBE 拖到300之后 侧栏=424.00` ⇒ 拖不动），但**渲染宽度**在 runner 上逐字是 `侧栏=424.00 详情(算)=423.00 分隔条=1.00 缝中心=424.50 倍率=1.00x`，而本机 2x 是 `423.50 / 423.50 / 424.00`。成因不是产品：`423.5pt × 1.0` 在 1x 栅格上不是整数 ⇒ AppKit 只能把一栏进位、另一栏退位。⇒ 判据按倍率拆口径（R555 那条方法）：**2x 那一档的 0.01 一字不动**，1x 那一档的界值**由栅格推出**（列差 ≤ 1/scale、缝心偏离 ≤ 1/(2·scale)），且真值表里同时钉住"1x 的真不对称（差 13pt）必须红"（刀 `M1484`），免得这一支变成藏红的洞。同一格里读到的反面事实：像素那把尺在 1x **连对象都没有**（`FOLD_SEAM_PIXEL … 缝列=-1.0pt 跳变=0.0 左墨=-1 右墨=0` ⇒ 整页平涂），所以它只能具名未运行（`容差 1.5`、`跳变地板 8` 一字未动），缝的像素证人目前**只有本机 2x 那一台签着**。
- **D6 版本分叉**：macOS **14+** 演全套（Metal 着色器：透视 + 渐进模糊 + 暗化）；macOS 12/13 演同一套几何与暗化、模糊退化为近似或不做。**README 的“macOS 12+”承诺不动**。两条路共用同一个“角度驱动”模型，判据与帧按系统版本分开口径（与既有 1x/2x 分口径同法）。
- **D7 触发**：双击列表上方“时间剪史”标题 + 可见的折叠按钮（带 `.helpLabel`）+ 应用菜单项 + ⌘\，四条入口走同一个 action。**不做手掰（scrub）**，以后另议。**系统分栏的中缝拖拽要禁掉**（两栏锁等宽之后它只会让人拖出不对称）。
- **D8 设置页调参面板**：放**五根滑杆**——速度（120–600ms）、模糊强度（0–1）、明暗变化（0–1）、眼距（400–2000pt，默认按桌面尺度折算约 900）、缓动曲线（4 预设，默认 ease-in-out）——外加“恢复默认”。不做隐藏调试器。滑杆必须复用现有 `.slider` 路径，并接进“恢复默认”的复位名册（现名册是九根）。每根滑杆都要能推动读数：推到两端读数不变 = 死控件 = 缺陷。
- **D9 样片**：设置页内一块约 260×180 的假“两页 + 中缝”，**必须调用主窗口同一套折页代码**（同一着色器、同一角度映射），内容只用固定测试文本，**不得出现用户真实剪贴板内容**。不允许为样片另写简化渲染（那是典型假绿：样片好看、主窗口难看）。
- **D10 reduce-motion**：系统开启“减弱动态效果”时时长为 0，一步到位，不留任何中间态。
- **D11 可中断**：过渡中再次触发以当前角度与当前 alpha 为起点反向，不排队、不留半折。
- **D12 验收**：逐帧硬判据 + 用户手感签字，**两边都过才算完成**；任一边不过就退回一步切换，并把“为什么这条观感做不到”写进台账。硬判据至少包含：角度单调、投影宽度按余弦律、模糊半径从铰链到自由边单调递增、亮度随角度单调下降、边框锐度不变、透明区 alpha 归零、框架只在透明之后缩一次、屏上帧间隔不超标。

## 3. 交付顺序（分几轮不重要，顺序是闸门）

1. **几何与读数重锚**：默认尺寸、50/50、锁比例、禁中缝拖拽；把引用 280/750 的判据与 356 张基线帧重锚。不动画。
2. **透明与框架**：非不透明窗口、点击穿透、阴影跟随形状、alpha 归零后框架缩一次；仍是一步切换。**这一轮要回答三个问题**（见 §4）。三问任一不过 ⇒ 停在这里，不写着色器。
   - **R568 的结果**：三问答完（两条成立、一条被证伪 ⇒ 用 D4a 那层底衬补平，观感一字未变）。**按闸门停在这里**：第③段没开工。另读到两条会把第③段判空的事实 —— 离屏通道分不出真黑与透明（646）、像素 alpha 不路由鼠标（647），第③段动笔前必须先有这两条的出路。
   - **R571 的进展（改文档在先）**：646 那条走**第一条出路**落地了一半 —— 新建的离屏通道（`captureTwoHalvesViaAlphaLayer`：视图树 `layer.render(in:)` 进自建 `premultipliedLast` 位图上下文、不预先铺底）在同一台机器上把 2x 与 1x 两种栅格都读到 `黑半区 a=255 / 透明半区 a=0 / 分得出=1` ⇒ "离屏能不能区分真黑与透明"从此**不再依倍率而定**；旧通道今天仍然 0，所以它的按倍率登记表一字未改。剩下的两件事：**646 的签字口径仍归用户**（本文档不替 D12 选档），**650** 要验这条通道对**产品真实视图树**是否同样保 alpha。647（像素 alpha 不路由鼠标）本轮未动，机制仍等用户定向。⇒ **三问仍未全过 ⇒ 第③段继续不开工。**

     ① **QuickPick 浮层那棵（产品今天唯一真有透明区的树）：保 alpha**。同一棵树、同一块栅格（840x600），**先让这棵树完整画一遍**（本轮用的前置是"先走一次旧通道 `cacheDisplay`"）再走新通道 ⇒ 两条通道的 alpha 三分数**逐字相等**（`旧三分=2096/16745/1319 新三分=2096/16745/1319`）且**逐点同 alpha 类、异类=0/20160**；2x 与 1x 两种栅格各读一次都 `分得出=1`（`2.00x 不透明=2096 全透明=16745` / `1.00x 不透明=474 全透明=4066`）。判据＝`TransparencyForensicsTests/testTheAlphaLayerChannelDrawsProductTreesWhereTheOldChannelDrawsThem` 与 `…KeepsRealTransparencyOfTheProductOverlayTree`，三把刀 M1499（铺底）/ M1500（内存行序翻一次）/ M1501（摘掉前置）全 CAUGHT。

     ② **有一个可复现的前置，第③段必须做进判据**：少了"先让这棵树完整画一遍"这一步，`layer.render` 对主窗那棵树读到**整幅 a=0**（`不透明=0/20160 有墨=0`，而且单次 `display` / `displayIfNeeded`（视图、hosting、窗口三种都试过，六臂）全叫不醒它）；对浮层则不是全空而是**少画一块** —— 肉眼看得见的那块是**选中行那层灰底**：旧通道同一颗探针读 `rgba=(220,220,220,255)`，缺前置的新通道读 `(0,0,0,0)`，分带数是 `带1 异类=748 / 带2 异类=1181`（合计 1929 颗采样）。而第③段要判的「右页 alpha 归零」给的**也是 a=0** ⇒ 在这条通道里「没画」与「归零」是同一个形状，光看"新通道看得见透明"会一路绿灯。这条已写成会红的判据（探针由旧通道选，新通道必须在同一颗探针上给同一类），不是注释里的告诫。

## 4. 还没验证的假设（第 2 轮的靶，谁也不许先当成已成立）

**R568 逐条给答案**（读数全部现读，通道 = `TransparencyForensicsTests`，本机 2x + 真机合成通道；判据卷日志 `/tmp/r568/readings2/capture-readings.log`）：

- 非不透明窗口下，侧栏的 vibrancy 材质会不会变淡或发花（材质的背景从"窗口自己"变成"桌面"）？
  **会 —— 这条假设被证伪。** 逐字 `TRANSPARENCY_MATERIAL_NEG 撤掉底衬 均值=0.6637 字墨=11582 品红漏出=319 均值移动=0.2702`：把测试夹具背景换成品红之后，侧栏那一列的平均亮度从 `0.9339` 掉到 `0.6637`（移动 0.2702，判据地板 0.05），并且 **319 个背景像素漏进了列表列**（材质没盖住那一列）。
  ⇒ 落地方式改成 **D4a**（下面那条），因为第③段真要"露桌面"之前，先把窗口改成非不透明就等于把一个用户能看见的退化提前塞进产品。
- 窗口阴影是否真的按内容 alpha 形状计算，从而不会在透明区拖出一条矩形阴影？
  **是 —— 这条假设成立**（在本机 2x 的真机合成通道上）。逐字 `TRANSPARENCY_SHADOW 正对照(整片不透明) 左带暗=0.0649 右带暗=0.0649 外扩=40pt 倍率=2.00x`（先证明这条通道看得见阴影，两半一样暗），再 `TRANSPARENCY_SHADOW 半片透明 左带暗=0.0631 右带暗=0.0017 判=套形状` ⇒ 透明那半下方几乎没有阴影 ⇒ **阴影跟可见形状，不会拖矩形**。
  ⚠ 这一条**只有真机通道判过**：runner 上 `REALSCREEN_SHADOW_NOT_RUN=env-off`（阴影画在框架之外，离屏缓冲里没有那一层）⇒ 第③段在 runner 上拿不到这条的证人。
- 现有取证通道（离屏捕获与真机截图）**能否区分"真黑"与"透明"**？
  **一条能、一条不能 —— 这是第③段的真阻塞。** 逐字 `TRANSPARENCY_CHANNEL 通道=离屏 位图=400x240 hasAlpha=1 黑半区=(r0,g0,b0,a255) 透明半区=(r0,g0,b0,a255) 分得出=0`：`cacheDisplay` 那条路**带着 alpha 通道仍然**把透明半区涂成不透明黑（与真黑逐字相同）⇒ 356 张基线帧与判据卷的离屏像素**都判不了"alpha 归零"**；而 `通道=真机 … 透明半区=(r234,g51,b247,a255) 分得出=1` ⇒ 只有真机合成通道能把背后的东西合成进来。

**R569 更正（runner 首跑把上面那半句判反了 —— 改账不删原文）**：本机 2x 的离屏读数是 `分得出=0`，而 **CI runner 1x 同一格读到 `透明半区=(r0,g0,b0,a0) 分得出=1`** ⇒ 准确的说法是**「离屏通道能不能保留 alpha 依捕获倍率而定」**，不是「离屏一律不能」。后果不是更轻而是更麻烦：同一套判据在两台机器上对同一个属性给**相反**答案，所以第③段验收之前必须**先定按哪一档口径签字**（与 644 同类，归用户）。判据本身已改成登记表：`registeredOffscreenVerdict(scale:)` 只收 2x / 1x 两个观测值，其余倍率具名不判（`OFFSCREEN_ALPHA_NOT_RUN=unregistered-scale`）⇒ 任一台翻了就红，结论不会悄悄过期。
**R571 进展（改文档在先，R569 那半句原文留着）**：这条通道现在**有一条两档一致的**。新通道 `captureTwoHalvesViaAlphaLayer` 把视图树 `layer.render(in:)` 进自建 `premultipliedLast` 位图上下文、**不预先铺底**、栅格由参数给，本机同一次运行逐字读到 `通道=离屏-alpha图层 位图=400x240 倍率=2.00x 黑半区=(r0,g0,b0,a255) 透明半区=(r0,g0,b0,a0) 分得出=1` 与 `位图=200x120 倍率=1.00x … 分得出=1`。排除过程（别的路都试过并留下读数）：`cacheDisplay` 给的位图 `bitmapFormat=0`（无 alpha 平面）；自建 alpha 位图喂给 `cacheDisplay` ⇒ 四个采样点全 a=0；`NSHostingView.draw(_:)` ⇒ 全 a=0；`dataWithPDF(inside:)` ⇒ 产品那棵树画不出；把旧位图再画进 alpha 上下文 ⇒ 上游没信息。**杠杆是"缓冲没有预先铺底"**（两把空刀的反面事实：图层 `isOpaque` 与 `bitmapInfo` 都不是它）。读法坑：同一条通道上 `colorAt` 把 raw `a=255` 读成 0 ⇒ 像素必须读原始字节。⇒ 本条从"真阻塞"降为"差两件事"：**646 的签字口径归用户**、**650 验产品真实视图树**。旧通道的按倍率登记表保持 `2x=涂成不透明黑 / 1x=保留 alpha` 一字未改。
**R572 进展（650 验完，R571 那段原文留着）**：对产品真实树判到了，三条都落进会红的判据里（通道串 `TRANSPARENCY_PRODUCT_ALPHA` / `TRANSPARENCY_PRODUCT_ALPHA_DRIFT`）：
· **浮层那棵树（产品今天唯一真有透明区的树）保 alpha** —— 同一棵树同一块栅格，新通道与旧通道的三分数逐字相等（`2096/16745/1319`）、逐点异类 `0/20160`，2x 与 1x 两种栅格同判；
· **前置是判据的一部分** —— 不先让 AppKit 把内容画一遍，`layer.render` 对主窗树读到整幅 `a=0`（`不透明=0/20160`、`有墨=0`；单次 `display`/`displayIfNeeded` 三种对象六臂全不够），对浮层则**少画选中行那层灰底**（旧 `(220,220,220,255)` vs 新 `(0,0,0,0)`，分带异类 `748+1181`）；而第③段要判的「alpha 归零」**也是 a=0** ⇒ 这一格判的是"旧通道选出的探针，新通道必须给同一类"，不是"新通道自己说看见了透明"；
· **主窗树今天没有真透明对象**（两通道都整幅 `a=255`）⇒ 具名 `PRODUCT_MAIN_TREE_TRANSPARENT_OBJECT_NOT_JUDGED=backing-covers-whole-tree`，不许拿浮层那棵替主窗那棵签字。
反面事实与自伤各一条，都进账：① 旧通道"分不出真黑与透明"**依对象而定**而非依通道恒真 —— 同一 2x 同一台机器，对两半已知的自绘夹具读 `分得出=0`（登记表未动），对浮层产品树读 `a0=16745`；② 本轮回炉前曾读到"两通道差 142 颗采样、逐点异类 5434"，差点把它写成"边缘带就是不同数"的契约 —— 真因是**我把这块缓冲的内存行序当成底朝上**（探针 `/tmp/r572/orient.log`：不翻 0/20160 异类、翻 y 5002、只翻 x 1565），方向修正后逐点 0 异类。教训：两通道对不上先怀疑自己的读法，再怀疑通道。

**R573 机制补注（651 · 改文档在先 · 三类层分开量，本机 2x）**：
· **类 A（AppKit 自绘 `draw(_:)` 的单视图）**：冷态就画得出 —— 五种候选调用（什么都不做 / `view.display()` / `cacheDisplay` 一遍 / `layer.display()` / `window.display()`）读数**逐字相同**（`子层=1 contents=1 不透明=1920/1920 分得出=1`）⇒ 这一类不需要前置。
· **类 B（`NSHostingView` 的 SwiftUI 层，就是 R571 那一格的对象）**：本机同样冷态就画得出（`子层=1 contents=0 不透明=1920 分得出=1`，五种调用同数）；**但 runner 上同一格冷态读到整幅 a=0**（`黑半区=(r0,g0,b0,a0)`）⇒ **"这一类需不需要前置"依机器而定，本机不能替它签字**。
· **类 C（产品浮层那棵容器树）**：只给根设 `wantsLayer` + `layoutSubtreeIfNeeded` ⇒ `子层=-1 全透明=20160 分得出=0`（层树根本没建出来）；再走一遍 `cacheDisplay` ⇒ `子层=6 不透明=176 分得出=1` ⇒ 对容器树，**递归 `wantsLayer` 只建层树，把内容画进 `contents` 的是 display 通路**。
· **类 D（`CAMetalLayer`）**：产品源码里引用 metal 的文件数现读 **0** ⇒ 今天不存在，**不编读数**，具名 `METAL_LAYER_NOT_RUN=no-shader-yet`。

### D4a 落地补注（R568，写文档而不是把判据改成能过）

- 窗口已经非不透明（`AppDelegate.makeMainWindow`：`isOpaque=false` + `backgroundColor=.clear`），而观感**一字未变**：同一条侧栏带在"设成不透明 / 设成非不透明"两臂下读到 `均值差=0.0000 品红漏出=0`，离屏捕获的 `TRANSPARENCY_STATE … 带内最小alpha=255 半透明样本=0/39342 洞范围=无`。
- 之所以两件事必须一起做：非不透明之后 SwiftUI 那层材质开始采样桌面（上面第一条）。补的那层**自己的不透明底衬**（`WindowBackingView` + `WindowBackingContainer`，底衬在下、内容在上）把它挡回来了。负臂 `M1480` 就是撤掉这层 ⇒ 同一条带立刻移动 0.2702。
- 两处设置只留**一处**（建窗那一处）：`WindowConfigurator` 里原本也要再写一遍，实测那样刀只能钉其中一处、另一处会把变异盖成空刀 ⇒ 收成单点，注释里写明。
- **代价（第③段必须还的账）**：加了底衬之后侧栏材质不再采样桌面 —— 今天它本来也不采样（窗口是 opaque 的），所以对用户没有变化；但第③段真要右页"露出桌面"时，必须把**那一侧**的底衬撤掉。本轮不撤（§3 的闸门顺序）。
