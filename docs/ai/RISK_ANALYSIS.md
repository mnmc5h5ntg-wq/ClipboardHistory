# AI 剪贴板风险分析

## 1. 工程风险

### 1.1 架构耦合

风险：AI 逻辑散落到 `HistoryStore`、View、MenuBar，后续难以替换。

缓解：新增独立 `Intelligence` 模块；UI 只消费推荐结果。

### 1.2 数据迁移复杂

风险：历史、收藏、AI 元数据、embedding 混在一个 Codable 文件中，迁移困难。

缓解：事实历史和 AI 派生数据分开持久化；引入 schema version。

### 1.3 延迟影响粘贴

风险：模型请求阻塞菜单栏或快捷键。

缓解：本地规则先返回；AI 异步刷新；设置超时预算。

### 1.4 macOS 权限碎片化

风险：窗口标题、选中文本、当前文件依赖 Accessibility、Automation 或 App 特定脚本。

缓解：按 capability 渐进启用；缺权限时降级。

## 2. 隐私风险

### 2.1 剪贴板高敏感

风险：密码、验证码、聊天截图、公司文档被发送到云端。

缓解：默认关闭云端；敏感检测；发送前预览；本地优先。

### 2.2 文件路径泄露

风险：文件名和路径也可能包含客户名、项目名、隐私信息。

缓解：文件上下文默认只发送扩展名和粗略类型，路径需单独授权。

### 2.3 调试日志泄露

风险：prompt、上下文、剪贴板原文写入日志。

缓解：默认不记录 prompt；调试模式显式开启；自动脱敏。

## 3. 用户体验风险

### 3.1 错误粘贴破坏信任

风险：Predictive Paste 一次错误就让用户关闭功能。

缓解：先做候选面板，不直接替代 `⌘V`；提供撤销和反馈。

### 3.2 推荐原因不可理解

风险：用户不知道为什么推荐这条。

缓解：每个推荐包含简短 reason。

### 3.3 设置复杂

风险：Provider、隐私、模型参数吓退普通用户。

缓解：简单/高级两层设置；默认本地规则可用。

## 4. 性能风险

### 4.1 embedding 成本

风险：每条历史都生成 embedding 会耗电、耗费 token、占空间。

缓解：只对文本/文件名生成；后台队列；去重；收藏和复用条目优先。

### 4.2 上下文采集卡顿

风险：Accessibility / AppleScript / Spotlight 查询慢。

缓解：快慢信号分层；主线程只读快照；慢信号缓存。

## 5. 法务和平台风险

- 云端 Provider 的数据使用政策不同，需要明确告知用户。
- Apple Intelligence API 可用性可能受地区、系统版本、设备限制。
- 未公证 App 会降低 AI 功能信任感，长期应解决 Developer ID notarization。

## 6. Predictive Paste 可行性结论

可行，但不应第一阶段承诺“自动知道用户想粘贴什么”。正确路径是：

1. 建立数据结构和反馈闭环。
2. 用规则推荐验证命中率。
3. 加入语义元数据提升召回。
4. 做候选面板式 Predictive Paste。
5. 最后才考虑高置信度自动粘贴。

这不是一个单纯模型问题，而是上下文、隐私、反馈和低延迟系统设计问题。
