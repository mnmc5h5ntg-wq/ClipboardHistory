## 8. 已知"离屏会说谎"的地方（不要拿帧当这些事的证据）

`sidebar-*` 与 `row-*` 帧里，**被选中的行会画成一整块黑**（文字看不见、缩略图还在）。
它精确跟随选中集合（`sidebar-multi-select` 三行选中 ⇒ 三块黑），因此判定为
`List` 的选中高亮在离屏 `cacheDisplay` 下的语义色伪影，与 D-025 那一族同源，
**不能据此判产品**；真机看 1.1/1.2 即可确认。帧基线仍按现状记录（68 帧，同代码连拍两次 sha 相同）。

## 批次 2（§5 F-1 / F-4 / F-5）里机器证不了、需要手点的

这些是**自动化确实够不着**的部分，不是"我忘了测"。每条都写了为什么机器量不到。

1. **导出 / 导入面板**。设置 →「数据」→「导出历史…」：确认保存面板出现、写出的 JSON 能打开、
   横幅里写了"图片 N 项未包含"。再到另一台（或清空后）「导入历史…」，确认
   条数、收藏、固定、来源 App 都回来，且**重复导入同一份不产生第二条**。
   机器做不了：`NSSavePanel` / `NSOpenPanel` 是系统模态面板，离屏夹具拿不到它。
   已代测的部分：`ArchiveTransfer` 的导出内容、导入合并与去重、以及"同 id 不复制第二份"
   都从 `HistoryStore.exportArchiveJSON()` / `importArchiveJSON()` 走真管线验过。
2. **OCR「只索引不落盘」的端到端**。开成只索引 → 复制一张带字的截图 → 用文字搜到它 →
   退出应用再打开，**搜索应当搜不到**（识别文本只在内存）；同时
   `~/Library/Application Support/时间剪史/history.json` 里这条不应带 `ocrText` 字段。
   改回落盘模式后重启应当又能搜到。
   更新（D-049）：**"识别文本落不落盘"现在机器已经验过了** —— 识别器可注入，
   用例走的是 `add` → 后台识别 → 写回 → 落盘/搜索 整条链，并且直接读 `history.json` 的字节。
   仍然需要你真机确认的只剩一件事：**Vision 对你真实截图的识别质量**
   （字很小、深色背景、混合中英文时能不能认出足够多的字，从而"搜得到"）。
   机器做不了那半条：跑真 OCR 在 CI 与本机都不稳，且它考的是系统识别器而不是本应用的逻辑。
3. **按 App 排除**。把某个密码管理器的 bundle id 加进「隐私」页名单 → 从它里面复制一段文本 →
   历史里**不应**出现；把同一条从别的 App 复制 → 应出现。默认名单里的
   「钥匙串访问」不需要任何配置就该挡。
   已代测的部分：`HistoryStore.add` 用注入的 defaults 域验过"名单里挡、名单外放、
   显式拖入优先、来源未知不挡"，以及默认名单含钥匙串。
4. **固定的观感**。固定一条 → 它跳到最前，行首出现 `pin.fill`；再复制新内容 → 固定项仍在最前；
   连灌超过上限（默认 500 条 / 30 天）的新记录 → 固定项不该被裁掉。多选后表头那颗 `pin` / `pin.slash`
   批量生效；单选时用详情右下角浮层新增的第四颗按钮。
   已代测的部分：排序 / 插入位 / 保留豁免、徽标像素（182 个差异像素、其余逐像素相同）、
   对比度 7.23:1 / 7.86:1。
   请人确认的是**观感**：徽标大小与位置在真实侧栏（带选中高亮底色）里是否还读得出来 ——
   离屏帧没有系统选中底色。
5. **详情浮层变高后的位置**。浮层从三颗按钮变四颗（约 187pt 高），窗口矮的时候会不会盖住正文，
   以及右下角距边 12pt 是否仍与系统控件间距协调。矮窗口（把主窗口拉到最矮）看一次。

## 批次 3（§4 U-4 / U-5）里需要人眼确认的

1. **搜索命中的观感**。搜一个正文里有的词：详情区应出现一块淡黄底、字仍清楚（实测对比度
   13.57:1 亮 / 5.60:1 暗）。换一条不含该词的记录，黄块必须**整体消失**，不许留在上一个位置
   （这条有自动化用例钉住清理逻辑，但"消失得干不干净"值得看一眼）。
2. **可读行长**。选中一段长文本（先从剪贴板复制几十个字）：正文应折行、列宽约 652pt、
   不再有横向滚动条；头部那行 meta 与正文**同左缘**。窗口拉窄时列跟着收窄、不换行到看不见的地方。
3. **空态的下一步**。搜索一个不存在的词 → 左栏应出现「清除搜索」，点它应回到全部记录且搜索框清空。
4. **菜单栏状态行**。触发一次推荐计算（或冷启动）后立刻打开菜单：应看到循环箭头图标 +
   "正在整理推荐…"（13pt）。这句以前是 11pt 且没有图标。
5. **12/13 的焦点环（本轮没改，需要你在旧系统上帮我判断）**。在 macOS 12 或 13 上点击左栏条目：
   整行会画一圈系统蓝色焦点环。这是 14 以下没有关闭 API 造成的，账本 D-039 说明了为什么
   本轮刻意**保留**它而不是先关掉：关掉之后画不出替代环，键盘用户就没有任何焦点指示了。
   如果你在旧系统上觉得那圈环确实碍眼、并且愿意接受自绘细环可能画错位置，请告诉我，我再做那一半。

## 批次 4（§5 F-2 / §4 U-2）需要真机手点的

1. **富文本往返**。先在「通用」页打开「保留富文本格式（RTF / HTML）」→
   在 Word/Pages/邮件里选中一段有**加粗和链接**的文字复制 → 打开时间剪史选中它再粘贴回 Word：
   格式应在。然后**关掉开关**重复一次：应当只有纯文本（这才证明开关是真的在管事）。
   已代测：`SystemClipboardWriter` 写进命名剪贴板后 RTF/HTML/纯文本三种表示都能读回、字节逐字相同、
   且 RTF 排在纯文本之前；采集侧开关关着时确实不抓；存档写盘再读回表示还在。
2. **旧记录没有格式**是预期的：富文本只在开关打开**之后**复制的记录里有，
   历史里已有的记录不会有（那一刻没抓）。
3. **体积**。开着开关复制几篇长文档后，`~/Library/Application Support/时间剪史/history.json` 会明显变大
   （每条上限 384KB）。这是这个功能的代价，不是异常；介意的话把开关关掉，已有的表示仍会留在存档里，
   直到那条记录被清理掉。
4. **多文件拖出**。选中一条"多个文件"的记录，从行里拖到 Finder 桌面：应当一次落地**全部**文件
   （以前这一类整条拖不动）。系统跟手的剪影就是那一行本身（带预览与数量"等 N 个"），
   所以"会带走什么"看得见 —— 这是刻意不换成自定义卡片的原因，见账本 D-040。
5. **拖出到只认单个文件的应用**（比如某些老编辑器）可能只拿到第一个路径，
   这是 `NSFilenamesPboardType` 这份表示的历史包袱；粘进历史仍完整。请留意是否遇到。

## 批次 5（§5 F-3 / §3 C-4）需要真机手点的

1. **⌃⌥⇧V 在别的 App 里能不能呼出浮层**。切到 Safari/微信/编辑器，按下组合键：
   浮层应出现且**光标已经在搜索框里**（不用点它就能打字）。打字 → 候选跟着变 →
   ↑↓ 移动 → 回车：那条内容被复制，并自动粘回你刚才所在的应用。Esc：浮层关闭，剪贴板不变。
   这一步机器测不了：在测试进程里 `NSApp.activate` 是空操作（spike 实测，见 D-041），
   所以"真按键能不能路由进这个面板"只能由你在真机上确认。
2. **组合键撞车**。如果你已经有别的 App 占着 ⌃⌥⇧V（比如自建的粘贴脚本），
   注册会失败并在「快捷键」页给出提示；改一个组合键即可。
   审计原文建议的 ⌘⇧V 被刻意让开了 —— 它在浏览器/编辑器里是"粘贴并匹配样式"。
3. **菜单栏入口**。菜单栏图标里应多出「快速选择…」一项，行为与快捷键完全一致
   （同一条 `AppCommand`，不是第二套实现）。
4. **运行时启动冒烟**。可以自己在终端跑一次（它只写临时目录）：
   `python3 scripts/launch_smoke.py 时间剪史.app`，应打印 `SMOKE_OK=1`。
   **注意**：如果你自己的 时间剪史 正在运行，这一步会真的开出第二个实例并多一个窗口
   （本轮实测 `InstanceGuard` 对这种直接 exec 的启动方式没挡住，已记为待查）。
   想干净地跑就先退出菜单栏里的那份，或者只看 CI 的同名步骤。
