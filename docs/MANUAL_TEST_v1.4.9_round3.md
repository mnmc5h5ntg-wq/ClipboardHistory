# 手工核对清单 · 第三轮审计整改（v1.4.8 之后）

自动化这一侧能钉住的都钉住了（`swift test` 355 例 / 10 skip / 0 失败），但下面这些**只能真机看**：
要么因为合成鼠标事件驱动不了系统表格（D-1 那三条），要么因为离屏渲染会说谎（选中底色）。
构建：`cd ClipboardHistory && swift build && open .build/arm64-apple-macosx/debug/时间剪史.app`。

## 1. 列表的选中与点击（D-1 换 `List(selection:)` 之后；拖选已按 D-034 放弃）

| # | 操作 | 期望 |
|---|---|---|
| 1.1 | 单击任意一行 | 选中它，详情区同步；**没有**半拍的延迟 |
| 1.2 | 在含 5 条文本的列表里，从第 1 行按下并拖到第 4 行再松手 | **拖出这一条**（半透明剪影跟着鼠标走），落到别的 App 即导出；**不会**扩成多行选中 —— 这是 D-034 的取舍：`List` 会把行内 `.onDrag` 提升成整行拖拽源，拖选与拖出不能共存，选了留拖出 |
| 1.3 | shift + 点击第 5 行 | 从上一条选中的扩到第 5 行（多选靠这个，不靠拖动） |
| 1.4 | ⌘ + 点击某行 | 加选/取消加选，不影响其他 |
| 1.5 | 单击某行后**双击**它 | 复制这一条并顶到列表最前（D-028 的行为没被 D-1 弄坏） |
| 1.6 | 点行首星标 | 只翻收藏，**不改变选中集合** |
| 1.7 | Tab 到列表后按 ↑ ↓ | 选中移动且选中行始终在视野里 |
| 1.8 | 鼠标点一下列表 | 列表外围**不该**出现整块蓝色焦点环（macOS 14+；12/13 平台无开关，出现属已知限制） |

## 8. 已知"离屏会说谎"的地方（不要拿帧当这些事的证据）

`sidebar-*` 与 `row-*` 帧里，**被选中的行会画成一整块黑**（文字看不见、缩略图还在）。
它精确跟随选中集合（`sidebar-multi-select` 三行选中 ⇒ 三块黑），因此判定为
`List` 的选中高亮在离屏 `cacheDisplay` 下的语义色伪影，与 D-025 那一族同源，
**不能据此判产品**；真机看 1.1/1.2 即可确认。帧基线仍按现状记录（68 帧，同代码连拍两次 sha 相同）。
